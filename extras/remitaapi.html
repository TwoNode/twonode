Remita APIs

Welcome to the API documentation for our comprehensive suite of services. We are committed to providing our customers with the most powerful, secure, and efficient API solutions. As part of our ongoing innovation, we are gradually rolling out enhanced APIs to replace our legacy systems, designed to bring improved performance and flexibility, without any disruption to your current integrations.

Our new APIs represent the future of our platform, built with modern architecture to meet evolving business needs. These APIs are already available for:

  • Agency Banking: Enabling agents to deliver essential banking services at scale.

  • Collections: Streamlined processing of collections for a wide range of Billers- from Government institutions to other Businesses.

  • Vending: A focused service for purchasing Airtime, Data, Electricity, and other utilities.

  • Funds Transfer: For our Funds Transfer service.

  • Verification: Offering reliable data verification for individuals and businesses.

At the same time, our First Generation APIs continue to operate reliably, providing critical functionality for your business. These include:

  • Invoice Generation: For easy and accurate management of invoices.

  • Payment Gateway: Enabling payments across multiple channels.

  • Recurring Payments: Automating your subscription and repeat payment needs.

You can confidently continue using both categorizations of our APIs, knowing that the services you rely on are fully supported. Our phased approach ensures a smooth transition to the new APIs at your own pace, with no compromise on performance or availability.

To begin using our APIs, follow the steps below depending on whether you are accessing our new services or the older services.

Get Biller Products

This API endpoint retrieves the products associated with a specific biller. The information obtained from this endpoint is essential for initiating a bill payment.

Custom Fields

Custom fields are additional fields specific to a biller’s product. A product may or may not have custom fields defined. If a product does not have custom fields, the custom fields array will be empty.

The available list of custom field types and their descriptions are as follows:

Custom Field Type Description
A Alphabets
AN Alphanumeric
N Numeric
D Date
DD Single select item list (no price/amount)
SL Multi select item list (no price/amount)
SP Multi select item list with price and amount
ALL Any value

To better understand the response and custom fields, you can compare the form fields with the response from the API by accessing the front end application of the products accessible from the provided link. Between the products Office Building and School Uniform, you will find an example of all custom field types.

Fields and Descriptions

The following fields and their descriptions are available in the response from this API:

Field Data Type Description
amount Numeric Bill amount, if there is a fixed amount on the product. If the product does not have a fixed amount, the value will be 0.
amountFixed Boolean 'true' if there is a fixed amount on the product, 'false' if not.
billPaymentProductId String The ID of the product.
billPaymentProductName String The name of the product.
currency String Currency that the product is being sold in.
customerId String The value of the validation item in question. For example, if meter number, then the actual meter number of the customer.
customFields Array List of custom fields associated with a product (if any).
display_name String The name that should be displayed for the custom field on a user interface.
DISPLAY_NAME String The value that should be used for the custom field dropdown in subsequent API calls.
required Boolean 'true' if the custom field in question is a required field, 'false' if not.
selectOptions Array The list of values if a custom field is a dropdown.
sortOrder String Order in which the custom field in question should be rendered on a user interface in relation to the other custom fields on that product.
type String Custom field type.
validation Boolean 'true' if the custom field in question requires validation, 'false' if not.
VALUE String The name that should be displayed for the custom field dropdown item on a user interface.

Validate Customer

This endpoint is required to be used only when a custom field on a Product requires validation See the sample response on the 'Get Biller Products' API.

Where relevant, the values returned in the response of this API (where the value is not NULL) should be returned in the relevant field in the 'Initiate Transaction' API.

Request Body

  • billPaymentProductId (String): The Product ID of the product that requires validation.

  • customerId (String): The value of the validation item in question, e.g., meter number, account number, etc.

Response

  • status (String): The status of the response.

  • message (String): A message related to the response.

  • data (Object):

    • customerId (String): The customer ID.

    • billPaymentProductId (String): The Product ID of the product.

    • name (String): Name of the customer associated with the Customer ID.

    • email (String): Email of the customer associated with the Customer ID.

    • address (String): Address of the customer associated with the Customer ID.

    • amount (Numeric): Bill amount (if applicable).

    • maximumAmount (Numeric): Maximum allowable amount for this bill. This will be null if not applicable.

    • minimumAmount (Numeric): Minimum allowable amount for this bill. This will be null if not applicable.

    • valueList (Array): List of values.
