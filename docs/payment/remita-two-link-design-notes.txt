So I have been thinking if this our present workflow is not working we can consider changing the approach.. 

Since after payment remita sends two links to the mail provided during the purchase. We treat it just like that

We provide the user to input the two links of the two receipts but not attached to S3 bucket just the way the Ai feature works for the fill form on new plan page. 

Link 1 - LASG receipt 
Link 2 - Remita receipt.. 

“This has to be smart such that it identifies if the user mis-match the upload for example upload remita receipt to Upload 1” 

Now what do we do with Link 1 - LASG receipt? 

1. We extract the information needed to map the url of the LASG ebs receipt - the transcode and trans id, we have the payer id and type in the user table already. 

2. We confirm the amount paid against the CoD fees.. 

Now what do we do with Link 2 - Remita receipt? 

We extract the RRR number and validate that it does not exist in the table. As the RRR number must be unique, so that users don't use the same receipt for several.


So to also add to our check that the two uploads are for the same transaction we extract 

From Link 1 we extract for example 

AssessRef<169767640-8154445-175>
Or
Teller-169767640-8154445-175

From Link 2 we extract

Lasg-169767640-8154445-175

These values must be the same.
