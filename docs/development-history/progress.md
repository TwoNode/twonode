## Live hotfixes to `main` (outside the rebuild)

- **2026-08-26 — QR payment verification bypass, fixed and pushed (`db9ade5`)**. Found while auditing for gaps like the MDA one below: `verifyQRServicePayment` marked any client-supplied reference `SUCCESS` and credited the surveyor's wallet with zero server-side confirmation — a reference is handed out for free by `initiateQRServicePayment` before any payment happens, so anyone could initiate then immediately verify without ever paying, getting free paywall access and fraudulently crediting real, withdrawable money into the surveyor's wallet. Fixed by calling Paystack's `transaction/verify` API and requiring a confirmed `success` status + matching amount before proceeding. Also fixed a bug the audit surfaced along the way: `PAYSTACK_SECRET_KEY` was cached at module scope from an `async` function without awaiting it, binding a `Promise` instead of a string — every Paystack `Authorization` header in that file (bank resolve, transfer recipient, and now transaction verify) was silently sending `"Bearer [object Promise]"`. Verified live with the real `PAYSTACK_TEST_SECRET`: the exploit now gets a genuine, authenticated Paystack rejection, not an auth-format failure. Same fix ported into `rebuild/foundations`'s already-migrated `qrEarningsService.ts` (`7ee2e21`) so Step 9's migration doesn't reintroduce it on merge.
